Logical Schema (Relational Model)

Conventions used:

    PK (Primary Key): Unique identifier.

    FK (Foreign Key): Reference link to another table.

1. USER (Handles authentication, profiles, and role hierarchy)

    ID_User (PK, INT, Auto-increment)

    First_Name (VARCHAR)

    Last_Name (VARCHAR)

    Email (VARCHAR, Unique)

    PasswordHash (VARCHAR)

    Username (VARCHAR, Unique)

    Karma_Score (INT, Default 100)

    Skill_Level (VARCHAR)

    Is_Player (BOOLEAN)

    Is_Organizer (BOOLEAN)

2. SPORT (Lookup table for sports disciplines)

    ID_Sport (PK, INT, Auto-increment)

    Sport_Name (VARCHAR)

    Default_Players (INT)

3. VENUE (Facilities and playing locations)

    ID_Venue (PK, INT, Auto-increment)

    Facility_Name (VARCHAR)

    Address (VARCHAR)

    Latitude (DECIMAL/DOUBLE)

    Longitude (DECIMAL/DOUBLE)

4. MATCH (Created match, absorbs 1:N relationships)

    ID_Match (PK, INT, Auto-increment)

    Date (DATE)

    Start_Time (TIME)

    End_Time (TIME)

    Total_Slots (INT)

    Available_Slots (INT)

    Price_Per_Person (DECIMAL)

    Match_Status (ENUM: 'OPEN', 'FULL', 'CANCELLED', 'COMPLETED')

    ID_Organizer (FK) -> References USER(ID_User)

    ID_Sport (FK) -> References SPORT(ID_Sport)

    ID_Venue (FK) -> References VENUE(ID_Venue)

5. JOIN_REQUEST (Bridge table resolving the N:M "Registration_Request" relationship)

    ID_Request (PK, INT, Auto-increment)

    Request_Date (DATETIME)

    Request_Status (ENUM: 'PENDING', 'ACCEPTED', 'REJECTED', 'CANCELLED')

    ID_Player (FK) -> References USER(ID_User)

    ID_Match (FK) -> References MATCH(ID_Match)
